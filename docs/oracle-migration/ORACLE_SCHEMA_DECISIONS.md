# Oracle Schema Decisions

**Status:** Phase 1 foundation decision record. No LMS table has been created in Oracle by this phase.

## Canonical source and scope

The accumulated active runtime schema in `lib/db.ts` is the starting source of truth for the later Oracle translation. It describes 19 active tables:

`users`, `courses`, `course_levels`, `course_enrollments`, `course_announcements`, `chapters`, `topics`, `lessons`, `lesson_segments`, `assignments`, `quiz_questions`, `submissions`, `meetings`, `private_lesson_requests`, `teacher_private_lesson_availability`, `student_lesson_completions`, `live_classes`, `live_class_participants`, and `lesson_live_broadcasts`.

It is not an Oracle migration file. Its PostgreSQL DDL and incremental alterations must be reconciled into reviewed, versioned Oracle migrations.

## Storage policies

| Concern | Oracle policy | Rationale |
|---|---|---|
| UUID | `VARCHAR2(36)`; generated by `crypto.randomUUID()` in application code | Preserves Cockroach UUID text values and foreign keys without RAW(16) conversion risk. |
| Boolean | `NUMBER(1)` plus `CHECK (column_name IN (0, 1))` | Stable across Oracle/driver versions; mapped only with `toDbBoolean` / `fromDbBoolean`. |
| JSON | Oracle JSON-capable column where supported by selected Autonomous version; otherwise JSON-constrained CLOB | Structured quiz answers and scores need explicit serialization, validation, and predictable reads. |
| Instant timestamp | `TIMESTAMP WITH TIME ZONE` | Maps the active `TIMESTAMPTZ` semantics without changing timezone behavior. |
| Date-only | `DATE` with documented date-only semantics | Used for assignment due dates; deadline business timezone remains a product decision before route migration. |
| Time-only | `VARCHAR2(5)` in `HH24:MI` form unless the later schema review selects a normalized date anchor | Oracle `DATE` includes a date component, so it is unsuitable for standalone weekly availability times. |
| Integer | `NUMBER(10,0)` for progress, order, duration, indexes, and counts | Safe JavaScript integer range for current LMS values. |
| Scores / points | `NUMBER(12,4)` unless route/domain review requires different precision | Supports fractional scoring while avoiding implicit driver/string assumptions. |

The database adapter does not automatically coerce every Oracle `NUMBER`: individual route migrations must choose numeric conversion and tests deliberately.

## Constraints and indexes

- Name new constraints consistently: `pk_<table>`, `fk_<child>__<parent>`, `uq_<table>__<columns>`, `ck_<table>__<rule>`, and `ix_<table>__<columns>`.
- Preserve primary keys, unique constraints, foreign keys, `ON DELETE` behaviors, and business checks from `lib/db.ts` after data-quality review.
- Recreate indexes from observed query paths, not by blindly translating the duplicate index artifacts. Re-evaluate the PostgreSQL partial broadcast index with an Oracle function-based index or query design.
- Use versioned migrations. Do not use repeatable `IF NOT EXISTS` DDL as a migration mechanism.

## Migration strategy

`database/oracle/runner/migrate.cjs` creates only the `schema_migrations` ledger after a data-dictionary check. It then applies immutable, ordered `.sql` files once and stores their SHA-256 checksums. Phase 1 creates the pattern but intentionally no LMS schema/data migration.

Run migrations explicitly with `npm run db:migrate:oracle`; do not run them from Vercel or `next build`. `npm run db:migrate:postgres` retains the existing Cockroach/PostgreSQL migration behavior for the temporary dual-provider period.

## Legacy artifact handling

Keep, but do not replay, `cockroachdb_schema.sql`, `sql/create_live_classes.sql`, `optimize-indexes.sql`, `fix-score-column.sql`, `supabase_schema.sql`, and `supabase/*.sql`. They are migration evidence only: they contain schema drift, duplicated live-class DDL, Cockroach repair logic, or a prior Supabase/RLS model that is not the active `pg` runtime schema.
